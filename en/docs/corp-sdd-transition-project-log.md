# Corp SDD transition — agent CLI + self-hosted model

Operator's corporate team (analysts, devs, manual testers, SDETs, DevOps) on a self-hosted ALM suite (tracker/wiki/git host) **Server/DC**-class deployment is moving to spec-driven development with **an agent CLI backed by a self-hosted open-weight model** (an OpenAI-compatible gateway), restricted network, **OSS-only, no new ALM marketplace plugins/licenses**. Product: big multi-module **JVM** codebase + **stream-processing jobs**, a visual dataflow tool, a query-language DB (not used), a **JS frontend**; an event bus/REST; columnar OLAP + cache + relational stores; downstream data consumers.

## Current state

As of 2026-07-18: **design APPROVED by operator** — [2026-07-17-corp-sdd-transition-design](2026-07-17-corp-sdd-transition-design.md) is final (incl. corrections: the visual dataflow tool out, no query-language DB, no savepoints, self-hosted CI, large-context self-hosted-model window, A→B phasing, existing JVM LSP MCP in baseline). Vault side of the design work is COMPLETE. Execution happens in the corp's own repos: **next = Phase 0** (baseline DORA-5 + DevEx pulse, disposer + lefthook + vendored commands in 2–3 pilot repos, system store skeleton, confirm the deployed JVM LSP MCP's name). This note stays active to receive rollout learnings/decisions if the operator brings them back → `2026-07-17-corp-sdd-transition-design.md`. Seven research rounds total (~4.5M subagent tokens). Decided: combo via selective vendoring; hub-and-spoke + federated drill-down index; disposer layer (verify-docs.sh, 4 triggers, Hermes write-boundary contract); intermediate-file state machine; **Variant A minimal tooling = decided baseline** (OpenSpec pinned + 3 vendored binaries + scripts, zero services); Variant B unconstrained-OSS documented (top-3: Zoekt+Serena, promptfoo, OTel+Langfuse); 4-phase rollout with evidence-grounded gates (opt-in→default→require only after >80% voluntary); metrics table (team-level, baseline-first, anti-metrics named). Next: operator reviews the doc; then corp-side implementation planning (out of vault scope).

## Key verified findings (sources = tool repos/trackers read directly, 2026-07-16/17)

### Foundation (option-independent, all verified OSS)
- The agent CLI ← OpenAI-compatible endpoint is documented first-class (`OPENAI_BASE_URL` env route; avoid a known model-providers config bug). Headless: `-p`, `--yolo`, `--approval-mode`, `--output-format json`, budgets `--max-wall-time/--max-tool-calls/--max-session-turns`, exit codes 41/42/44/52/53/55, `<AGENT>_UNATTENDED_RETRY=1`.
- **A generic tracker/wiki MCP bridge** (MIT): self-hosted tracker/wiki access via PATs, 93 tools, shared HTTP multi-user, READ_ONLY_MODE.
- **A one-way git→wiki publisher** (Apache-2.0): mirror is policy-enforced, manual edits overwritten.
- **The git host has no built-in pipelines** — CI = a self-hosted CI system (MIT; its git-host plugin is distributed independently, not through the ALM marketplace). PR creation via the git host's PR-create REST endpoint, PAT bearer.
- The ALM's **native issue↔commit linking** (built into the self-hosted suite, not marketplace) gives tracker↔git-host linking free.
- Held-out gates (agent-invisible, per reward-hacking finding ~27pp gap growth per 10× LOC): **Pact + pact_broker + can-i-deploy** (MIT); **Karapace/Apicurio** (Apache-2.0) — Confluent SR is NOT OSS; a schema-migration tool with a columnar-OLAP adapter (Flyway Community + official plugin, Apache-2.0) or golang-migrate (MIT, dirty-state caveat); a relational-migration linter (**Squawk**) + **pgroll** (expand/contract). **Avoid Atlas** (EULA binary; lint + the OLAP adapter paywalled) and **Liquibase 5+** (FSL, not OSS). Isolation pattern = GitHub "pwn requests" split, translated to CI credential-scoped jobs.
- No credible enterprise SDD case studies with measured outcomes exist (vendor numbers debunked) — org must baseline & measure its own cycle-time/defect metrics.

### OpenSpec (Fission-AI/OpenSpec, MIT, 61k★, v1.6.0)
- Brownfield-first delta specs (ADDED/MODIFIED/REMOVED), team workflow change=folder=branch, never touches git; an agent-CLI adapter ships (`openspec init --tools <your-agent>`).
- **`/opsx:apply` contains zero test/TDD/verify instruction** (apply-change.ts read directly); `verify` is expanded-profile-only + non-blocking; **rules are advisory** (#826); fast-path can **archive with no delta spec silently** (#1212 open); flat spec dir known not to scale (own workspace-architecture.md + #662); stores=Beta and solve multi-repo, not multi-module; config repo-global not per-module; README recommends frontier models (mismatch w/ the self-hosted model); TOML commands deprecated — works via the agent CLI's auto-migration shim (behavioral caveat; upstream issue open); `/opsx:` colon vs `opsx-` palette naming bug (#680); zero ALM-suite-specific anything (grep-verified).
- Community already runs it WITH superpowers and asks upstream to absorb TDD (#973) / package as superpowers skill pack (#780).

### superpowers (obra/superpowers, MIT, v6.1.1)
- 14 skills; bodies verifiably harness-agnostic (grep: ~zero Claude-tool references); TDD/systematic-debugging/verification-before-completion directly attack org's happy-path-testing pain.
- **No working agent-CLI integration**: PR #1136 draft/conflicting — live smoke test on the agent CLI **failed auto-trigger** (called `new-app`, not brainstorming); PR #516 stalled; parent Gemini CLI was "advisory, not executable" (#128, on ice), then EOL'd & support removed (PR #1846) — cached v6.1.1 still ships broken GEMINI.md include. Port ≈ 1–3+ wks with architectural risk; fallback = explicit invocation.
- Injection fragility class vs OpenAI-compatible gateways documented (#894 — multiple system messages break the agent-CLI family; fixed by user-message injection). The self-hosted model over the gateway unverified.
- No spec lifecycle (dated freeform files), no tracker/wiki integration, single-human design, per-individual install (mitigable: commit skills per-repo).

### Stack-fit
- The JVM framework: integration-test context cache-busting turns 2-min suites into 15-min — TDD skill must encode fast-unit/slow-integration tier split; DI wiring bugs surface only in slow tier.
- Stream-processing jobs: the operator-test harness + embedded-cluster tests = fast TDD viable; needs savepoint/state-schema-compat gate; the stream processor's own upstream AGENTS.md is a live precedent for discipline docs.
- **A visual dataflow tool = SDD scope exception**: no test loop for flow logic (flowfile attrs invisible in JSON export); delta-spec narrative + human review only. Its registry component deprecated → git-based registry clients; the git host's DC support needs a minimum tool version on that dataflow tool — verify org's version.
- Query-language DB: (skipped — not used by the org); if adopted later, query-generation hallucination needs a schema-fetch-before-write rule.
- The JS frontend: highest agent maturity, config-agnostic, best pilot zone; a SaaS visual-diff service is under consideration (flag vs OSS-only) — OSS alt: Storybook test-runner + Playwright diffs.
- Real context budget on shared self-hosted gateway ≈ 32K–128K, not marketed 1M → favors small delta specs + subagent isolation.

### Combo seams (adversarial read of both sources)
- Collisions: explore vs brainstorming; flat tasks.md vs writing-plans granularity; **inference-tolerant `verify` vs evidence-demanding VBC creates false-positive archive path**; trigger ambiguity on "implement this".
- Clean seam: OpenSpec never touches git ↔ finishing-a-development-branch owns git lifecycle.
- Context stacking worst case 12–18k tokens; mitigations: lazy skills, explicit slash-commands (zero ambient cost), subagent isolation.
- Glue needed: router/precedence, one spec-truth (openspec/), disable writing-plans, tasks.md→per-task TDD subagent loop, verify→lint + VBC→gate, archive→finish-branch handoff + the tracker's issue↔commit-linking convention. All corporate-owned; no upstream precedent.

## Decision log
- 2026-07-17 — Operator constraints added: the agent CLI provided as-is (no serving/infra design); design must be **product-agnostic re the ALM suite** (org migrating to own MCP-capable tools — bridges = generic MCP, not a named tracker/wiki bridge or git→wiki publisher); L3 enforcement stays helicopter-level; #1 design goal = minimal friction per role ("AI must simplify, not add work"). Role-by-role design + 6-verb command surface presented.
- 2026-07-17 — Drift design: **requirements durable, plans disposable** — delta specs written against behavior at propose time; design/tasks generated only at implementation pull time (spec early, plan late); staleness surfaces as ordinary git rebase conflicts on openspec/specs. Mid-implementation spec-reality mismatch → classify (spec-incomplete / code-surprising-but-compatible / spec-unimplementable) → amend the still-mutable delta on the same branch, analyst approves a diff; each discovery ratchets the living spec toward code reality.
- 2026-07-17 — Operator confirmed combo direction ("truth is somewhere between" OpenSpec-only and superpowers-only).
- 2026-07-17 — State-awareness design: three-layer state (living capability specs = behavior truth, updated by archive; GENERATED pointer maps ~1k tokens regenerated from code = navigation, never prose facts; handwritten notes scoped to decisions/WHY only, nested nearest-file-wins). Rule: state files point at truth, never cache it — contract facts (field names, endpoints) verified against live code/schema at authoring time. Evidence: context rot replicated (Chroma 18 models; coherent prose WORSE than shuffled; NoLiMa degradation by 32K; RULER effective = 50-65% of advertised; lost-in-the-middle U-curve); stale docs = confident wrong specs.
- 2026-07-17 — Master-spec-repo verdict (operator wanted all specs central, none in code repos): **rejected all-central; recommended hub-and-spoke** — code repos keep own openspec/ (atomic spec+code PRs preserved); ONE central system store (OpenSpec stores-beta topology verified from primary docs: store = standalone planning repo, code repos keep own root, references read-only, one checkout/machine, NO auto-sync, NO pinning, beta) holds cross-repo contracts + system map + conventions + generated capability index. Placement rule: spec lives where its implementing PR lands; no single home → store. Evidence against all-central: no atomic cross-repo PR (kills same-PR amend loop), orthogonal-docs-repo = documented drift topology, Google g3doc colocates for atomicity, schema registries succeed via publish+pin+gate not central storage, Backstage pattern = central index + colocated authorship, OpenSpec itself defaults colocated. Honest gap: no direct case study either way exists.
- 2026-07-17 — Workflow reliability note: sonnet subagents failed StructuredOutput twice on the stores deep-read (one returned literal "test" placeholder — caught via journal, not trusted); stores facts re-verified inline from primary doc instead. Pattern repeated in refine round (3 placeholder failures total) → reran research on inherit model, succeeded.
- 2026-07-17 — **State/index architecture finalized** (research + adversarial critic): operator's federated drill-down index CONFIRMED = Backstage architecture (per-repo descriptor + thin central catalog). Decisive evidence: hand-maintained catalog content is what kills catalogs (Riftmap: "parsed graph cannot go stale — the source is the input"; unowned catalogs die ~6mo) → maximize generated fraction. Hardened 3-layer model: L-maps split deterministic build-graphs (depgraph-maven-plugin/jdeps — aider-style PageRank breaks on multi-module JVM duplicate symbols) vs per-module ranked maps, ≤1-2k tokens, CI regenerate+drift-fail; L-specs upgrade verify→EMBED contract snippets from source (embedme --verify), `sources:` front-matter freshness flagging, ArchUnit for checkable claims; L-notes = append-only ADRs, agent-drafted at archive (50% ADR abandonment → automate). New 4th primitive: self-hosted Zoekt (Apache-2.0; Sourcegraph NOT OSS since 2023, Kythe maintenance-mode) via MCP for cross-repo reads. Drill-down contract: central=navigation only, repo wins by construction, SHA-freshness check, ≤3 content hops, search-first. Critic budgets: HP1 single-repo fits 32K (~28-30K); HP2 3-repo blows 32K (35-48K, needs 128K tier) + NO atomic cross-repo merge — accepted openly; HP3 store-owned contract amendment = 2-3 PR fan-out. Acceptance test: "if a repo's index can be wrong while its CI is green, the design has failed." Split-brain lint: contract facts live in exactly ONE place, spokes link never restate. Minimal build: pilot 2-3 repos (schema+generator+CI drift), store as plain git repo, drill-down skill, full HP1 automation. NOT yet: stores-beta, umbrella orchestration, wiki automation, release-aware index; Zoekt when cross-repo work starts.
- 2026-07-17 — (proposed, pending operator) Combo via **selective vendoring**: OpenSpec pinned + explicit commands; 4–6 vendored corporate skills committed per-repo; corporate router command replaces bare `/opsx:apply`; CI holds enforcement. Rationale: backend triple-weakness (slow JVM-framework tests, self-hosted-model tool-calling gap, 32–128K real context) means neither layer alone suffices; full superpowers port is high-risk (auto-trigger failed live) while vendoring sidesteps it.

- 2026-07-17 — **Disposer layer + intermediate-files design** (2 strong-model agents, hands-on verified tooling): (1) local-first validation — ONE `verify-docs.sh` (caps table → check-jsonschema/ajv schema+front-matter → lychee --offline --include-fragments → embedmd -d → regenerate-and-diff), run 4 ways from one code path: agent post-write self-check (write→verify→stderr→regenerate), lefthook pre-commit (blocking ERRORs — corp agent commits aren't backups, unlike vault advisory), on-demand, CI backstop. lefthook picked (Go single binary, no Node needed for JVM devs); pre-commit.com rejected (Python + network clones); vendor lychee+embedmd binaries.
