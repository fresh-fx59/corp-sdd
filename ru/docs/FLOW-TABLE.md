# Поток Corp SDD — большая таблица

Эта таблица сопоставляет каждый шаг поставки истории с командой Corp SDD, операцией
OpenSpec, принятой дисциплиной Superpowers, детерминированными скриптами и выходным условием.
Краткая версия тех же семи шагов — [`FLOW.md`](FLOW.md), схема — [`FLOW-SCHEMA.md`](FLOW-SCHEMA.md).

Все шесть навыков `corp-*` — корпоративные переработки, основанные на Superpowers; Corp SDD
не запускает исходную среду Superpowers. Каждая команда начинается с детерминированной
проверки `repository-state.sh`, а каждый вызов OpenSpec ниже — это плейсхолдер, который
установка заменяет реальной сгенерированной командой порта. «Хук» означает, что пример конфигурации Lefthook
установлен. «Проверки верификации» означают `verify-docs.sh` и три дочерних скрипта.
Столбец ценности сравнивает покрытие рабочего процесса, а не измеренные результаты пилота.

## Быстрое подключение продуктовой команды

Подключение рассчитано на быстрый, простой и безопасный старт: без масштабной миграции и необходимости заранее описывать всю унаследованную систему. Первым результатом должно стать реальное поставленное изменение, а не проект по документированию. Фактические сроки должны быть подтверждены пилотом.

1. Выбрать одну продуктовую команду, 2–3 связанных репозитория и небольшое реальное изменение.
2. Один раз установить общий комплект Corp SDD и дать каждой роли короткий понятный сценарий работы.
3. Выполнить пилот, не заменяя действующие инструменты, роли, ревью или процесс тестирования команды.
4. Сравнить с исходным уровнем понятность, длительность цикла, количество дефектов, усилия на ревью и отзывы команды.
5. Устранить выявленные препятствия, затем по желанию подключать следующие команды; сохранить возможность отката.

## Вспомогательная автоматизация за пределами семи шагов поставки

Эти скрипты есть в стартовом комплекте, но текущие тела семи команд не вызывают их напрямую:

- `check-openspec-root.sh` проверяет, что OpenSpec указывает на текущий Git-репозиторий. Руководство по настройке требует выполнить его до работы со спецификацией, но `corp-spec` сейчас его не вызывает.
- `sync-submodules.sh` регистрирует, инициализирует и проверяет репозитории, перечисленные системным хранилищем, как Git-подмодули в `system-store/submodules/`; он только добавляет и никогда не удаляет привязку. `aggregate-index.mjs` создаёт компактный межрепозиторный каталог возможностей.
- `index-all.sh` создаёт необязательный индекс поиска кода Zoekt по этим подмодулям и завершается ошибкой, если для индексации символов отсутствует Universal Ctags.

Файлы команд и навыков — это шаблоны для корпоративной версии интерфейса агента. Точный синтаксис слэш-команд OpenSpec, инструменты трекера и wiki, автоматизация pull request и команды тестирования проекта должны быть зафиксированы и проверены на этапе исследования возможностей этой версии.
