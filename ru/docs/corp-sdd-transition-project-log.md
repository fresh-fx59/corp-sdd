# Corp SDD transition — агент CLI + self-hosted модель на self-hosted ALM-системе

Корпоративная команда оператора (аналитики, разработчики, ручные тестировщики, SDET, DevOps) на self-hosted ALM-системе (трекер/вики/git-хост) **Server/DC** переходит на разработку через спецификации с **корпоративным портом агент CLI на базе самостоятельно развёрнутой open-weight модели** (OpenAI-совместимый шлюз), в изолированной сети, **только OSS, без новых плагинов/лицензий marketplace ALM-вендора**. Продукт: большая многомодульная кодовая база **JVM-стек** + **стрим-процессор**, **визуальный dataflow-инструмент**, **JS-фронтенд**; шина событий/REST; колоночное OLAP-хранилище/кэш/реляционное хранилище; нижестоящие потребители данных.

## Current state

По состоянию на 2026-07-18: **дизайн ОДОБРЕН оператором** — [2026-07-17-corp-sdd-transition-design](2026-07-17-corp-sdd-transition-design.md) финализирован (в т.ч. корректировки: визуальный dataflow-инструмент исключён, графовой БД нет, без savepoints, self-hosted CI, большое контекстное окно self-hosted модели, фазирование A→B, существующий JVM LSP MCP в базовой поставке). Часть работы над дизайном на стороне vault ЗАВЕРШЕНА. Исполнение происходит в собственных репозиториях корпорации: **дальше = Phase 0** (базовые DORA-5 + пульс DevEx, диспозер + lefthook + вендоренные команды в 2–3 пилотных репозиториях, скелет системного стора, подтвердить имя развёрнутого JVM LSP MCP). Эта заметка остаётся активной, чтобы принимать уроки/решения по раскатке, если оператор к ним вернётся → `2026-07-17-corp-sdd-transition-design.md`. Всего семь раундов исследований (~4,5M токенов субагентов). Решено: комбо через выборочное вендоринг; hub-and-spoke + федеративный индекс с drill-down; слой диспозера (verify-docs.sh, 4 триггера, контракт границы записи Hermes); машина состояний на промежуточных файлах; **Variant A minimal tooling = решённая базовая поставка** (OpenSpec с фиксированной версией + 3 вендоренных бинарника + скрипты, ноль сервисов); Variant B с неограниченным OSS задокументирован (топ-3: Zoekt+Serena, promptfoo, OTel+Langfuse); 4-фазная раскатка с гейтами на доказательствах (opt-in→default→require только после >80% добровольного использования); таблица метрик (уровня команды, baseline-first, с явно названными анти-метриками). Дальше: оператор просматривает документ; затем планирование внедрения на стороне корпорации (вне области vault).

## Ключевые проверенные находки (источники = репозитории/трекеры инструментов, прочитанные напрямую, 2026-07-16/17)

### Фундамент (не зависит от варианта, всё — проверенный OSS)
- Апстримный агент CLI ← OpenAI-совместимый эндпоинт задокументирован как first-class (маршрут через env `OPENAI_BASE_URL`; известен баг modelProviders, из-за которого этого пути стоит избегать). Headless: `-p`, `--yolo`, `--approval-mode`, `--output-format json`, бюджеты `--max-wall-time/--max-tool-calls/--max-session-turns`, коды выхода 41/42/44/52/53/55, `<AGENT>_UNATTENDED_RETRY=1`.
- **Generic MCP-мост для трекера/вики** (MIT): трекер/вики Server/DC через PAT, 93 инструмента, общий HTTP для многих пользователей, READ_ONLY_MODE.
- Один из вариантов (Apache-2.0): односторонний издатель git→вики (зеркало обеспечивается политикой, ручные правки перезаписываются).
- **У git-хоста нет встроенных pipelines на Server/DC** — CI = self-hosted CI (MIT; его плагин для git-хоста распространяется отдельно, а не через marketplace ALM-вендора). Создание PR через PR-create REST-эндпоинт git-хоста (`POST /rest/api/latest/projects/{k}/repos/{slug}/pull-requests`), bearer с PAT.
- Нативное **issue↔commit linking** ALM-системы (встроено в DC, не marketplace) даёт связку трекер↔git-хост бесплатно.
- Held-out гейты (невидимые для агента, по находке о reward-hacking рост разрыва ~27 п.п. на каждый 10× LOC): **Pact + pact_broker + can-i-deploy** (MIT); **Karapace/Apicurio** (Apache-2.0) — Confluent SR НЕ OSS; **Flyway Community + официальный плагин для колоночного OLAP-хранилища** (Apache-2.0) или golang-migrate (MIT, оговорка про dirty-state); **Squawk** (линтер реляционных миграций) + **pgroll** (expand/contract). **Избегать Atlas** (бинарник по EULA; lint + адаптер для колоночного OLAP-хранилища за paywall) и **Liquibase 5+** (FSL, не OSS). Паттерн изоляции = разделение по образцу GitHub «pwn requests», перенесённое на CI-задачи с областью, ограниченной по учётным данным.
- Достоверных корпоративных кейсов SDD с измеренными результатами не существует (цифры вендоров опровергнуты) — организация должна сама снять baseline и измерять собственные метрики cycle-time/дефектов.

### OpenSpec (Fission-AI/OpenSpec, MIT, 61k★, v1.6.0)
- Делта-спеки brownfield-first (ADDED/MODIFIED/REMOVED), командный поток изменение=папка=ветка, git никогда не трогает; поставляется адаптер под агент CLI (`openspec init --tools <your-agent>`).
- **`/opsx:apply` не содержит ни одной инструкции про тесты/TDD/verify** (apply-change.ts прочитан напрямую); `verify` — только в расширенном профиле и неблокирующий; **правила носят рекомендательный характер** (#826); fast-path может **молча заархивировать без делта-спеки** (#1212 открыт); плоская директория спек, как известно, не масштабируется (собственный workspace-architecture.md + #662); сторы = Beta и решают проблему мультирепо, а не мультимодульности; конфиг общий на репозиторий, а не на модуль; README рекомендует frontier-модели (несоответствие с самостоятельно размещённой open-weight моделью); TOML-команды устарели — работает через shim авто-миграции агента CLI (#838 открыт); баг именования палитры `/opsx:` через двоеточие vs `opsx-` (#680); ноль всего, что связано с self-hosted ALM-системой (проверено через grep).
- Сообщество уже запускает его ВМЕСТЕ с superpowers и просит upstream впитать TDD (#973) / упаковать как skill pack superpowers (#780).

### superpowers (obra/superpowers, MIT, v6.1.1)
- 14 skills; их тела проверяемо независимы от harness (grep: ~ноль ссылок на инструменты Claude); TDD/systematic-debugging/verification-before-completion напрямую бьют по боли организации с тестированием только happy-path.
- **Нет рабочей интеграции с агентом CLI**: PR #1136 черновой/конфликтующий — живой smoke-тест на агенте CLI **провалил авто-триггер** (вызвался `new-app`, а не brainstorming); PR #516 заглох; родительский Gemini CLI был «рекомендательным, не исполнимым» (#128, заморожен), затем EOL и поддержка удалена (PR #1846) — кешированный v6.1.1 всё ещё поставляет сломанный include GEMINI.md. Портирование ≈ 1–3+ недели с архитектурным риском; запасной вариант = явный вызов.
- Задокументирован класс хрупкости инъекций против OpenAI-совместимых шлюзов (#894 — несколько system-сообщений ломают агента CLI; чинится инъекцией через user-сообщение). Самостоятельно размещённая модель поверх OpenAI-совместимого шлюза не проверена.
- Нет жизненного цикла спек (датированные свободные файлы), нет трекера/вики, дизайн на одного человека, установка на каждого индивидуально (смягчаемо: коммитить skills в каждый репозиторий).

### Соответствие стеку
- JVM-фреймворк: сброс кеша контекста в интеграционных тестах превращает 2-минутные наборы в 15-минутные — skill TDD должен закодировать разделение на быстрые-юнит/медленные-интеграционные уровни; баги проводки DI всплывают только на медленном уровне.
- Стрим-процессор: тестовый харнесс оператора + встроенный тестовый кластер = быстрый TDD жизнеспособен; нужен гейт savepoint/совместимости схемы состояния; **собственный AGENTS.md у апстримного проекта стрим-процессора** — живой прецедент документов о дисциплине.
- **Визуальный dataflow-инструмент = исключение из области SDD**: нет тестового цикла для логики потоков (внутренние атрибуты потоков невидимы в JSON-экспорте); только нарратив делта-спеки + ревью человеком. Встроенный реестр потоков устарел → git-ориентированные клиенты реестра; **поддержка git-хоста DC требует минимальной версии инструмента** — проверить версию у организации.
- СУБД с языком запросов, склонным к галлюцинациям (не используется в итоговом дизайне): миграционный инструмент в стиле Flyway существует; галлюцинации языка запросов требуют правила fetch-схемы-перед-записью (официальный MCP-сервер для такой СУБД имеет get-schema).
- JS-фронтенд: наивысшая зрелость агента, независим от конфигурации, лучшая пилотная зона; визуальный SaaS-diff-сервис — это SaaS (флаг против only-OSS) — OSS-альтернатива: Storybook test-runner + Playwright diffs.
- Реальный бюджет контекста на общем самостоятельно развёрнутом шлюзе ≈ 32K–128K, а не рекламируемый 1M → в пользу маленьких делта-спек + изоляции субагентов.

### Швы комбо (адверсариальное чтение обоих источников)
- Коллизии: explore vs brainstorming; плоский tasks.md vs гранулярность writing-plans; **толерантный к инференсу `verify` vs требующий доказательств VBC создаёт путь ложно-положительной архивации**; неоднозначность триггера на «implement this».
- Чистый шов: OpenSpec никогда не трогает git ↔ finishing-a-development-branch владеет жизненным циклом git.
- Наложение контекста в худшем случае 12–18k токенов; смягчения: ленивые skills, явные slash-команды (нулевая фоновая стоимость), изоляция субагентов.
- Нужен клей: роутер/приоритет, единая истина спек (openspec/), отключить writing-plans, tasks.md→цикл субагента TDD на задачу, verify→lint + VBC→гейт, archive→передача в finish-branch + конвенция native issue-linking для трекера. Всё в собственности корпорации; upstream-прецедента нет.

- 2026-07-17 — Оператор подтвердил направление комбо («истина где-то между» only-OpenSpec и only-superpowers).
