# Эксплуатация

## Ежедневная входная проверка

Начинайте внутри выбранного репозитория, а не в корне системного хранилища:

```bash
export REPO_ROOT="$(git rev-parse --show-toplevel)"
bash "$REPO_ROOT/tools/repository-state.sh" inspect
```

Перед новой историей выполните `prepare-base`, создайте `feature/<TICKET>` от
показанной базовой ветки, опубликуйте upstream и выполните `assert-change <TICKET>`.
При продолжении прерванной работы используйте `--allow-dirty` только после проверки
каждого локального изменения. Ненулевой код — жёсткая остановка.

Инструмент не делает reset, clean, rebase, не удаляет ветки, не меняет неизвестное
грязное дерево и не скрывает локальные коммиты. База определяется по
`CORP_BASE_BRANCH`, локальному `corp.baseBranch`, `.gitmodules` родительского
хранилища, удалённому `develop`, затем удалённой ветке по умолчанию.

## Процесс

1. `corp-spec`: проверяет репозитории, готовит базы, создаёт ветки истории и явно
   вызывает OpenSpec new и continue до появления proposal и delta spec.
2. `corp-plan`: подтверждает ветку и создаёт актуальные design и tasks.
3. `corp-implement`: подтверждает ветку, входит в OpenSpec apply и применяет Corp TDD.
4. `corp-review`: проверяет состояние и запускает OpenSpec verify до ревью человеком.
5. `corp-test-plan` и `corp-autotest`: строят проверки из утверждённых сценариев.
6. После merge `corp-archive` готовит настроенную базу и запускает OpenSpec archive.

Точные вызовы OpenSpec хранятся в `port-facts.md` и установленных командах.
Проверяйте их заново после обновления порта или OpenSpec.

## Обновление привязок проекта

Повторно получите привязки для сохранённого project id. Предпочитайте MCP, если
инструмент доступен; иначе обновите тот же нормализованный JSON вручную. Затем:

```bash
export STORE_ROOT="$(git rev-parse --show-toplevel)"
bash "$STORE_ROOT/tools/sync-submodules.sh" \
  --inventory "$STORE_ROOT/project-repositories.json" --store-root "$STORE_ROOT"
git -C "$STORE_ROOT" submodule status
```

Новые привязки добавляются, совпадающие инициализируются, исчезнувшие показываются,
но сохраняются. Несовпадение URL, опасный путь или чужой каталог останавливают
операцию до изменений.

Для получения обновлений после проверки локального состояния:

```bash
git -C "$STORE_ROOT" submodule foreach --recursive 'git fetch --prune origin'
```

Безопасное перемещение базы делайте через `repository-state.sh prepare-base` внутри
каждого репозитория. Не используйте массовый checkout или reset.

## Межрепозиторные изменения

Используйте один родительский ticket для контракта системного хранилища и один
дочерний ticket на репозиторий. Сначала создаётся контракт. Delta spec репозитория
ссылается на него по store id и spec id, но не повторяет форму. Порядок согласования:
контракт первым. Порядок реализации и merge: producer, consumers, затем контракт
хранилища. Изменение контракта останавливает зависимую работу.

После обновления индексов репозиториев пересоберите каталог:

```bash
node "$STORE_ROOT/tools/aggregate-index.mjs" --strict "$STORE_ROOT"
```

## Восстановление состояния

| Состояние | Значение | Безопасное действие |
|---|---|---|
| detached HEAD | нет безопасной ветки истории | найдите ветку-владельца; сохраните коммиты |
| dirty при подготовке базы | правки могут быть уникальны | изучите и осознанно закоммитьте или перенесите |
| ahead от upstream | есть неопубликованные коммиты | изучите и опубликуйте либо перенесите до переключения |
| только behind | доступно безопасное обновление | выполните `prepare-base` для fast-forward |
| ahead и behind | расхождение | остановитесь; выберите merge или rebase по правилам команды |
| неверная ветка | работа может относиться к другой истории | сохраните работу и только потом переключайтесь |
| orphaned binding | списка больше нет в inventory | подтвердите владение до ручного удаления |

## Необязательный индекс Zoekt

Zoekt необязателен. Процесс работает без него. На выделенном хосте установите
`zoekt-git-index` и Universal Ctags, затем:

```bash
bash "$STORE_ROOT/tools/index-all.sh" --store-root "$STORE_ROOT" \
  --index-dir "${CORP_ZOEKT_INDEX_DIR:-$STORE_ROOT/.cache/zoekt/index}"
```

Инструмент читает `.gitmodules`, проверяет все пути до индексации, требует именно
Universal Ctags и сообщает об отсутствующих подмодулях. Не ведите второй список.

## Обновление комплекта

Получите изменения `corp-sdd`, изучите diff, затем повторите этапы 1, 2 и 5–8
установки. Не перезаписывайте хранилище из `system-store-template/`. Скопируйте
актуальные инструменты, команды и навыки, замените OpenSpec-плейсхолдеры в
установленных копиях, выполните негативные тесты и отдельно закоммитьте каждый
Git-репозиторий.
