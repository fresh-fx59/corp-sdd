# Процесс Corp SDD

Это краткое описание процесса на русском языке. Установка описана только в
[`SETUP.md`](SETUP.md), а ежедневная работа — только в
[`OPERATIONS.md`](OPERATIONS.md).

Те же семь этапов одной схемой: [`FLOW-SCHEMA.md`](FLOW-SCHEMA.md).

## Граница установки

Установщик размещает `system-store` рядом с этим репозиторием. Репозитории продукта
подключаются как Git-подмодули в `system-store/submodules/`. Отдельного каталога клонов нет.

1. На первом этапе установки получить связанные с проектом репозитории через доступный MCP.
2. Если MCP недоступен, вручную собрать тот же список с полями `name`, `url` и `baseBranch`.
3. Проверить список и записать его в `system-store/project-repositories.json`.
4. Запустить `sync-submodules.sh`. Скрипт регистрирует, инициализирует и обновляет только объявленные подмодули.
5. Установить команды, инструменты и шесть автономных навыков `corp-*` из комплекта.
6. Подставить локальные имена команд OpenSpec в заполнители команд.
7. Запустить приёмочные проверки до начала работы.

MCP упрощает поиск репозиториев, но не обязателен для установки. Внешний Superpowers тоже
не обязателен: необходимые инженерные правила уже входят в комплект.

## Жизненный цикл разработки

| Этап | Команда Corp | Обязательное действие OpenSpec | Проверка состояния репозитория |
|---|---|---|---|
| Спецификация | `corp-spec` | Запустить найденные `opsx new`, затем `opsx continue` до появления `proposal.md` и `spec.md`. | Сначала проверить состояние; подготовить настроенную базовую ветку до создания ветки изменения. |
| План | `corp-plan` | Запускать найденную `opsx continue` до появления `design.md` и `tasks.md`. | Требовать точную ветку изменения из трекера и чистое состояние. |
| Реализация | `corp-implement` | Войти в найденную `opsx apply`, затем выполнять задачи по Corp TDD. | Требовать точную ветку изменения; незакоммиченные файлы разрешаются явно. |
| План тестов | `corp-test-plan` | Прочитать изменение OpenSpec и составить покрытие сценариев. | Проверить состояние и локальную ветку изменения, если она есть. |
| Запуск тестов | `corp-autotest` | Обновить доказательства OpenSpec после выполнения уровней тестов. | Требовать точную ветку изменения; незакоммиченные файлы разрешаются явно. |
| Ревью | `corp-review` | Запустить найденную `opsx verify` до углублённого ревью кода. | Проверить состояние и локальную ветку изменения, если она есть. |
| Архив | `corp-archive` | Запустить найденную `opsx archive` после слияния pull request. | Сначала подготовить и проверить настроенную базовую ветку. |

Каждая команда вычисляет `REPO_ROOT`, `STORE_ROOT` и пути инструментов во время запуска.
Команды не зависят от абсолютного пути разработчика или текущего рабочего каталога.

## Доказательство

Запустите шесть скриптов из `tests/` для обоих языковых комплектов. Они проверяют синхронизацию
подмодулей, безопасность веток, агрегацию, индексацию, вычисление путей, объём документации,
резервный путь без MCP, явные действия OpenSpec и отсутствие старых путей клонов.
