# Состояние репозитория Corp SDD

Используй `tools/repository-state.sh` до чтения кода, создания ветки, планирования,
реализации, ревью, генерации тестов и архивации. Ненулевой результат — жёсткая
остановка; сначала сохрани и объясни текущее состояние.

## Режимы

| Намерение | Команда | Гарантия |
|---|---|---|
| Только изучение | `inspect` | Показывает базу, ветку, upstream, dirty, stash, ahead/behind |
| Новая работа | `prepare-base` | Переходит на базу и делает только проверенный fast-forward |
| Работа по истории | `assert-change <TICKET>` | Требует точную `feature/<TICKET>`, upstream и отсутствие behind |
| Продолжение правок | `assert-change <TICKET> --allow-dirty` | Та же проверка ветки; известные правки разрешены |

База определяется по `CORP_BASE_BRANCH`, локальному Git-параметру
`corp.baseBranch`, затем `.gitmodules` родительского хранилища. Без них используются
`origin/develop` и удалённая ветка по умолчанию.

## Ошибки

При ошибке прочитай показанное состояние и команду восстановления. Не изменяй
репозиторий до решения, кому принадлежит локальная работа.

Инструмент никогда не делает reset, clean, rebase, force checkout, автоматическое
изменение stash или удаление веток. Не обходи эту защиту ручной короткой командой.

## Частые ошибки

- Corp-команда запущена из корня хранилища вместо `system-store/submodules/<repo>`.
- `git fetch` ошибочно принят за обновление рабочей ветки; используй `prepare-base`.
- Ветка ahead принята за мусор; это может быть единственная копия коммита.
- `--allow-dirty` применён к неизвестному состоянию; он только для понятной
  прерванной работы в точной ветке истории.
