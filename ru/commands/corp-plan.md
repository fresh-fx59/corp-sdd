description: Генерация design + tasks для одобренного изменения, против СЕГОДНЯШНЕГО кода (поток разработки)
---
Спланируйте изменение {{args}}. Следуйте скилам corp-drill-down (все факты о системе) и corp-verification.
Предусловие: proposal + делта-спека существуют и одобрены — если нет, ОСТАНОВИТЕСЬ
и скажите, чего не хватает.
1. Прочитайте делта-спеку, research.md и живые спецификации, которые она изменяет. Прочитайте ТЕКУЩИЙ код
   затрагиваемых модулей (используйте corp-drill-down; добавляйте новые проверенные факты в research.md).
2. Напишите design.md: подход, файлы/классы для правки, точки интеграции, рискованные места с пометкой
   почему. Держите его короче 200 строк — он одноразовый; глубина живёт в коде и спеке.
3. Напишите tasks.md: сначала строка-заголовок состояния («As of YYYY-MM-DD — stage 1 (planned), next: task 1»),
   затем задачи с чекбоксами. Каждая задача = один цикл red-green, который ревьюер мог бы проверить в одиночку: называет
   реализуемый сценарий, тест для написания, область кода. Порядок: рискованные/неизвестные задачи ПЕРВЫМИ.
4. Запустите: bash tools/verify-docs.sh — зелёный до передачи.
5. Представьте план разработчику на одобрение. Не начинайте реализацию.
