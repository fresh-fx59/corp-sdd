Реализуйте изменение {{args}}.
Дисциплина: следуйте скилам corp-tdd (весь код), corp-verification (все заявления о готовности),
corp-debugging (любой неожиданный сбой), corp-drill-down (любой факт о системе).
0. Прочитайте строку-заголовок состояния в tasks.md + research.md СНАЧАЛА — возобновляйте, никогда не выводите заново.
1. Если design.md/tasks.md отсутствуют или устарели (изменился дайджест индекса): перегенерируйте их
   сейчас против текущего кода (планы одноразовы, спеки долговечны).
2. Для каждой задачи: напишите падающий тест из сценария спеки (быстрый юнит-уровень; медленный
   интеграционный уровень только на границах задач) → реализуйте → запустите → зафиксируйте свидетельство в
   tasks.md → отметьте чекбокс → перепишите строку-заголовок состояния.
3. При расхождении спеки/кода ОСТАНОВИТЕСЬ и классифицируйте: (а) спека неполна → составьте поправку к
   делте на этой ветке, уведомите аналитика через трекер, ждите; (б) код удивляет, но
   спека права → перегенерируйте задачи, отметьте в research.md; (в) нереализуемо → остановитесь, эскалируйте.
4. После каждой записи файла в openspec/ или docs/: bash tools/verify-docs.sh.
5. Готово = все чекбоксы отмечены + весь набор тестов зелёный + verify-docs зелёный. Никогда не заявляйте
   готовность без вставленного свидетельства последнего прогона тестов.
